# HWiNFO 多電壓軌監測紀錄

使用 HWiNFO 記錄主機板與 GPU 的電壓感測讀值，觀察 +12V、+5V、+3.3V 與 GPU 供電相關欄位，並說明軟體感測資料的判讀方式與限制。

> 本專案為軟體感測監測案例，不是 PSU 硬體認證或完整 ATX 符合性測試。感測讀值落在參考範圍內，不代表 PSU 的所有功能均正常。

## 專案目的

- 辨識不同電壓軌與感測欄位。
- 區分主機板、GPU 供電輸入與核心電壓。
- 透過時間序列資料觀察讀值變化。
- 建立可追溯的資料整理與結果說明方式。
- 清楚交代軟體監測與硬體實測的差異。

## 目前狀態

已取得 HWiNFO 記錄的局部表格截圖，包含日期與時間、主機板電壓，以及 GPU 電壓欄位。

本 README 先整理監測範圍、初步觀察與判讀限制。目前尚未在本專案中提供完整原始 CSV、全程統計或正式 PASS／FAIL 結論。

## 監測範圍

### 主要電壓軌

| 監測項目 | 感測欄位 | 說明 |
|---|---|---|
| 主機板 +12V | `+12V [V]` | 觀察主機板回報的 +12V 讀值 |
| 主機板 +5V | `+5V [V]` | 觀察主機板回報的 +5V 讀值 |
| 主機板 +3.3V | `+3.3V (AVCC) [V]` | 保留原始感測名稱，獨立觀察 |
| 主機板 +3.3V | `+3.3V (3VCC) [V]` | 保留原始感測名稱，獨立觀察 |

欄名以原始 HWiNFO CSV 為準。AVCC 與 3VCC 不因標稱電壓相同就合併統計；實際感測位置與意義需參考硬體文件。

### GPU 補充觀察

| 感測欄位 | 用途 |
|---|---|
| `GPU PCIe +12V 輸入電壓 [V]` | 觀察 GPU 回報的 PCIe +12V 輸入讀值 |
| `GPU 8-pin #1 輸入電壓 [V]` | 觀察 GPU 回報的外接供電輸入讀值 |
| `GPU 線路電壓 (avg) [V]` | 作為補充讀值，不假設其等於本次記錄的時間平均 |
| `GPU Misc0 輸入電壓 [V]` | 保留觀察；未確認硬體對應前，不指定其物理量測位置 |

不將主機板 +12V、GPU PCIe 與 GPU 8-pin 的讀值混合計算平均，也不直接將它們的差異解釋為線材壓降。

### 不套用主要電壓軌範圍的欄位

- CPU 核心電壓（Vcore）。
- GPU 核心電壓。
- CPU NB／SoC、DIMM 等其他電壓。
- VBAT 與用途尚未確認的 VIN 欄位。

這些欄位可能具有不同的工作電壓與動態調節機制，不能套用 +12V、+5V 或 +3.3V 的參考範圍。

## 電壓篩查參考

本專案採用標稱電壓 ±5% 作為主要三條電壓軌的資料篩查參考，包含上下邊界。

| 電壓軌 | 標稱值 | 參考下限 | 參考上限 |
|---|---:|---:|---:|
| +12V | 12.00 V | 11.40 V | 12.60 V |
| +5V | 5.00 V | 4.75 V | 5.25 V |
| +3.3V | 3.30 V | 3.135 V | 3.465 V |

以上是本專案採用的篩查門檻，不是對所有 ATX 版本、測試條件或感測位置的完整規範解讀。GPU 輸入端讀值也不能直接當成 PSU 輸出接頭端的量測結果。

若讀值超出範圍，應先核對感測器識別、量測精度與測試情境，必要時以合適儀器確認，不直接判定 PSU 故障。

## 完整資料的統計方式

以下為後續取得完整 CSV 時採用的方法，並非已完成的分析結果。

每個記錄檔、每個感測欄位分別計算：

| 統計項目 | 用途 |
|---|---|
| 有效筆數 | 確認可用資料量 |
| 缺值或無效筆數 | 檢查資料完整性 |
| 最小值 | 觀察已記錄樣本中的最低讀值 |
| 最大值 | 觀察已記錄樣本中的最高讀值 |
| 平均值 | 描述有效樣本的平均讀值 |
| 最大值減最小值 | 描述本次取樣中觀察到的讀值範圍 |
| 超出參考範圍的筆數 | 找出需進一步確認的樣本 |
| 起訖時間與取樣間隔 | 交代記錄涵蓋範圍 |

不同測試情境、記錄檔與感測器不混合統計。空白或無效內容不以 0 V 代替。

若取樣間隔不一致，一般算術平均僅代表樣本平均，不等同時間加權平均。

**最大值減最小值不是電源漣波量測結果。**

## 資料保存原則

- 原始 CSV 保留不變；欄位擷取、格式轉換與統計另存副本。
- 截圖用於展示欄位與局部讀值，不能取代完整原始資料。
- 若製作處理後的資料，應保留來源檔名、时间與感測欄位名稱。
- 實際測試情境、硬體型號與軟體版本只填寫已確認的資訊。
- 公開前檢查是否包含不宜公開的個人資訊。

## 監測限制

1. **軟體讀值不是接頭端直接量測。**  
   資料由硬體感測器與軟體回報，可能受到校正、解析度、欄位對應與更新頻率影響。

2. **取樣可能漏掉短暫事件。**  
   約 2 秒一次的記錄無法捕捉所有快速壓降、瞬態或高頻雜訊。

3. **不能以此評估漣波。**  
   漣波與快速瞬態需要適當儀器、探測方式與測試條件。

4. **顯示精度不等於量測準確度。**  
   即使欄位顯示三位小數，也不代表感測器具有相同準確度。

5. **感測位置不同，讀值可能不同。**  
   主機板與 GPU 的讀值不可未經確認就視為同一節點。

6. **缺少負載資訊時，不推論負載調節能力。**  
   不能僅由電壓截圖判定待機、滿載、功耗或特定壓力測試狀態。

7. **不能判定整顆 PSU 的健康狀態。**  
   本專案未涵蓋效率、保護功能、保持時間、可靠度或完整負載測試。

## 與 Python 電壓工具的區別

- **本專案**：整理 HWiNFO 多電壓軌監測資料與感測限制。
- **`voltage-checker-python`**：以指定 CSV 格式展示 +12V 分類與報告產生邏輯。

+12V 專用工具不能直接用來判讀 +5V 或 +3.3V；HWiNFO 原始 CSV 也需要先完成欄位轉換，才能符合該工具的輸入格式。

## 結語

本專案重點是感測欄位辨識、資料整理與有依據的結果解讀。現階段提供監測方法及局部觀察，不以未完成的統計或軟體感測截圖宣稱硬體通過認證。
